# Лабораторная работа № 4. Виртуализация и Контейнеры

## Что здесь происходит

В этой работе вам нужно развернуть небольшую контейнеризированную систему. Создать виртуальную машину с Linux, установить в ней Docker и запустить два независимых HTTP-сервиса на основе Nginx. Сервисы должны быть доступны по разным портам и уметь обращаться друг к другу по сети Docker.

Ваша задача - показать, что оба контейнера действительно работают, взаимодействуют через сеть и управляются независимо, значит остановка одного не должна останавливать второй. **Писать приложение или Dockerfile не нужно.**

### Что нужно использовать

`Oracle VirtualBox` - для создания виртуальной машины.

`Ubuntu Server 24.04 LTS` - гостевая операционная система. Для виртуальной машины достаточно 2 виртуальных процессоров, 2 ГБ оперативной памяти и диска 20 ГБ, но если есть возможность - выделите побольше ресурсов.  Сетевой адаптер можно оставить в режиме NAT.

`Docker` - для запуска контейнеров. Можете использовать готовый образ `nginx:alpine`.

### Айди и порты

Каждый студент использует собственный идентификатор `STUDENT_ID` в формате `фамилия-группа` (латиницей, строчными буквами), например `ivanov-601`. Этот идентификатор должен присутствовать в ответах обоих HTTP-сервисов. Если работаеете в команде - придумайте какой-то себе айди. 

Порты назначте любые из доступных, не дефолтные, каждому сервису свой порт:


Имена контейнеров - **`vnc-a`** и **`vnc-b`**, имя пользовательской сети Docker - **`vnc-net`**. Оба контейнера должны подключаться к этой сети. Совпадение портов у разных студентов не вызывает конфликтов: каждый запускает контейнеры в собственной виртуальной машине.

### Что нужно сделать

**Часть 1. Ручной запуск**

1. Создайте виртуальную машину в VirtualBox, установите Ubuntu Server и убедитесь, что внутри нее есть доступ к Интернету.
2. Установите Docker и Docker Compose. Проверьте, что Docker может запускать контейнеры.
3. Подготовьте две разные HTML-страницы (достаточно обычного текста) с содержимым `Service A: <STUDENT_ID>` и `Service B: <STUDENT_ID>`.
4. Запустите два контейнера Nginx с именами `vnc-a` и `vnc-b`. Каждый должен отдавать свою страницу на указанном порту. Файлы страниц подключите к контейнерам из директорий виртуальной машины с помощью bind mount, чтобы их можно было менять без пересоздания контейнера.
5. Подключите оба контейнера к сети `vnc-net`. Проверьте, что из `vnc-a` можно получить страницу `vnc-b`, обратившись к нему по имени контейнера.
6. Остановите `vnc-b` и убедитесь, что `vnc-a` продолжает отвечать. Затем снова запустите `vnc-b` и проверьте, что его страница доступна.

Будет достаточно просто текста:

```text
Service A: ivanov-601 Service A responding. 
Service B: ivanov-601 Service B responding. 
```


**Часть 2. Docker Compose**

7. Создайте файл **`compose.yaml`**, который описывает ту же систему: два сервиса на основе `nginx:alpine`, имена контейнеров `vnc-a` и `vnc-b`, выбранные порты, подключение тех же файлов через bind mounts и сеть `vnc-net`. Сеть уже создана в первой части работы - используйте ее в Compose как **`external`**, не создавая вторую сеть.
8. Остановите и удалите контейнеры, запущенные вручную. **HTML-файлы и сеть `vnc-net` удалять не нужно.**
9. Из директории с `compose.yaml`, запустите систему командой `sudo docker compose up -d`.
10. Убедитесь, что два контейнера снова запущены и выполняются все требования первой части: страницы доступны по тем же портам, в ответах присутствует ваш айди, из `vnc-a` можно обратиться к `vnc-b` по имени. Остановка и повторный запуск `vnc-b` не должны прерывать работу `vnc-a`.


### Проверка результатов

Проверяйте все **в терминале виртуальной машины**. Настраивать проброс портов VirtualBox на основной компьютер не требуется.

`sudo docker ps` - оба контейнера должны быть в состоянии `Up`, с правильными именами и опубликованными портами.

`curl http://localhost:1234` и `curl http://localhost:4321` - каждый запрос должен возвращать текст соответствующего сервиса с вашим `STUDENT_ID`.

`sudo docker exec vnc-a wget -qO- http://vnc-b` - запрос из первого контейнера ко второму должен вернуть страницу сервиса B. Здесь используется имя контейнера, а не `localhost`.

После остановки B запрос к нему должен перестать работать, а A - продолжить отвечать. После повторного запуска B оба сервиса снова должны быть доступны.

После перехода на Compose дополнительно проверьте `sudo docker compose ps`: сервисы должны быть запущены. Убедитесь, что `compose.yaml` находится на виртуальной машине и запуск вы делали **через Compose**, а не повторными командами `docker run`.
